## Architecture

```
match-engine.ts (pure functions)
  │
  ├── normalizeProductName()     lowercase, strip punctuation, collapse spaces
  ├── tokenizeProductName()      split into token array
  ├── matchByBarcode()           exact barcode → 100%
  ├── matchByCode()              exact product code → 100%
  ├── matchByExactName()         normalized name equality → 100%
  ├── matchByToken()             token overlap ratio → 80-95%
  ├── matchByFuzzy()             Levenshtein distance → 70-84%
  └── matchProduct()             main entry point
```

## Examples

### Exact Match (100%)

```
Input:  "Paracetamol 500mg"
DB:     "Paracetamol 500mg"
→ normalized: "paracetamol 500mg" = "paracetamol 500mg"
→ confidence: 100%, method: exact_name ✅
```

### Token Match (90%)

```
Input:  "Paracetamol Tab 500"
DB:     "Paracetamol 500mg Tablet"
→ raw tokens:    ["paracetamol","tab","500"]
→ product tokens: ["paracetamol","500mg","tablet"]
→ matched: "paracetamol" (in both)
→ overlap: 1/3 vs 1/3 = 33%... too low
```

Wait — "tab" ≠ "tablet", "500" ≠ "500mg". Let me improve example:

```
Input:  "Paracetamol 500 mg"
DB:     "Paracetamol 500mg Tablet"
→ raw tokens:    ["paracetamol","500","mg"]
→ product tokens: ["paracetamol","500mg","tablet"]
→ matched in raw: ["paracetamol"] (1/3)
→ matched in prod: ["paracetamol"] (1/3)
→ overlap: min(0.33, 0.33) = 0.33 → 31% — too low
```

Hmm, the current token match is exact substring — "500" ≠ "500mg". This could miss many real matches. The token match works best when tokens are exact substrings.

```
Input:  "Amoxicillin 500 Capsule"
DB:     "Amoxicillin 500mg Kapsul"
→ raw tokens:    ["amoxicillin","500","capsule"]
→ product tokens: ["amoxicillin","500mg","kapsul"]
→ match: "amoxicillin" only
→ overlap: 0.33 → below threshold → falls to fuzzy
→ fuzzy: distance=8, maxLen=25 → (25-8)/25 = 68% → below 70%
→ UNMATCHED ❌
```

This is a known limitation. Future v2 can use:
- Stemming (remove "mg", "tab", "capsule" suffixes)
- Synonym dictionary (capsule ↔ kapsul, tablet ↔ tab)
- ML-based embeddings (future)

### Fuzzy Match (82%)

```
Input:  "Parasetamol 500mg"  (typo)
DB:     "Paracetamol 500mg"
→ normalized: "parasetamol 500mg" vs "paracetamol 500mg"
→ Levenshtein: distance=2 (se→ce)
→ maxLen: 18
→ confidence: (18-2)/18 = 88%
→ method: fuzzy ✅
```

### Unmatched (0%)

```
Input:  "XYZ Brand New Drug 100mg"
DB:     No similar products
→ barcode: no match
→ code: no match
→ exact: no match
→ token: no match
→ fuzzy: all < 70%
→ method: unmatched ❌
→ candidates: []
```

## Failure Cases (known limitations)

| Case | Reason | v2 Fix |
|------|--------|--------|
| "500 mg" vs "500mg" | Token is exact substring | Stemming suffixes |
| "Capsule" vs "Kapsul" | Language difference | Synonym dictionary |
| "Paracetamol 500" vs "Paracetamol 650" | Different strengths → different products | Correctly unmatched ✅ |
| Typo "Paraetamol" | 2 char difference | Fuzzy catches this ✅ |
| "Tab" vs "Tablet" | Abbreviation | Abbreviation expansion |

## Complexity

| Function | Time | Space |
|----------|------|-------|
| `normalizeProductName` | O(n) | O(n) |
| `tokenizeProductName` | O(n) | O(n) |
| `matchByBarcode` | O(p) | O(1) |
| `matchByCode` | O(p) | O(1) |
| `matchByExactName` | O(p × n) | O(1) |
| `matchByToken` | O(p × n) | O(k) |
| `matchByFuzzy` | O(p × n × m) | O(m) |
| `matchProduct` | O(p × n × m) | O(p) |

n = name length, p = product count, m = max name length, k = token count

With p ≤ 500 (typical pharmacy catalog), worst case is ~500 × 30 × 30 = ~450K operations — well within browser budget.

## Future OCR Integration

```ts
// OCR parsed item → match engine
import { matchProduct } from "./match-engine";
import { productRepo } from "@/lib/repository-instances";

async function matchOcrItem(rawName: string, barcode?: string): Promise<MatchResult> {
  const products = await productRepo.getRawProducts({ isActive: true });
  const refs = products.map(p => ({
    id: p.id,
    name: p.name,
    barcode: p.barcode,
    code: (p as any).code,
  }));
  return matchProduct(rawName, refs, barcode);
}
```
