# 5. DECISIONS THAT WORKED

| Decision | Why It Worked |
|----------|---------------|
| **Type-level invariant enforcement** | `AllocationEntry` tidak memiliki field `sellingPrice` — compiler mencegah pelanggaran. Lebih kuat dari dokumentasi. Lebih cepat dari grep. |
| **batchId as canonical relationship key** | Found during Board Review — `entries[i]` coupling antara `AllocationDraft` dan `PriceSnapshot` diganti dengan `.find(p => p.batchId)`. Robust terhadap perubahan sorting/filtering di masa depan. |
| **Story-by-story Engineering Gate** | Setiap story = deliverable konkrit. Review fokus. Tidak ada "review 16 changes sekaligus". |
| **ADR-006 treated as separate track** | Ditemukan saat sprint → dibuat ADR → status PROPOSED. Tidak dicampur dengan implementasi sprint. |
| **PricingRule as strategy interface** | Future-ready tanpa over-engineering. Interface defined, implementation empty. Promo/Member/BPJS tinggal implement interface. |

# 12. LESSONS LEARNED

1. **Type-level enforcement beats documentation.** Inv-2 tidak mungkin dilanggar karena `AllocationEntry` tidak memiliki field `sellingPrice`. Ini adalah lesson dari V10.2 yang diaplikasikan di V10.3.

2. **batchId is the canonical domain key.** Array index coupling antara dua domain object adalah fragile pattern. Board Review menemukan ini — review oleh orang lain sangat penting.

3. **ADR for business rule changes.** Ketika menemukan potensi perubahan business rule (Sales Unit Policy), ADR-006 adalah respons yang tepat — bukan langsung coding.

4. **Scope freeze discipline works.** Dua sprint berturut-turut dengan 0 scope creep. Blueprint LOCKED adalah kuncinya.

5. **Pre-existing test failures are accumulating noise.** 16 failures tidak berkurang dari V10.2 ke V10.3. Ini harus di-address di V10.4.

6. **Three-domain separation is clean.** Allocation, Pricing, Validation — masing-masing dengan bounded context yang jelas. Tidak ada kebingungan tanggung jawab.
