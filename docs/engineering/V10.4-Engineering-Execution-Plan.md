| Attribute | Value |
|-----------|-------|

| File | `src/lib/cashier/transaction-freezer.ts` (NEW) |

**Acceptance Criteria**:
```
□ TransactionFreezer.freeze() is PURE:
    □ No React, Zustand, Supabase, store access
    □ Deterministic — same input → same output
    □ All monetary via normalizeRupiah()

    □ No setters, no mutation methods
```

## Story 3: CheckoutSessionService

**Goal**: Application Service yang mengorkestrasi seluruh domain service.

**Critical Rule**: CheckoutSessionService adalah ORCHESTRATOR — bukan God Object. Ia tidak memiliki business logic sendiri. Ia hanya memanggil domain service secara berurutan.

### Task 3.1 — CheckoutSession Type + Lifecycle

| Attribute | Value |
|-----------|-------|
| Priority | P0 |
| Engineering Estimate | 30 min |
| Dependencies | None |
| File | `src/lib/cashier/types.ts` (extend) or `src/services/checkout-session.service.ts` (inline) |

**Acceptance Criteria**:
```
□ CheckoutSession type defined:
    □ sessionId, cartId, tenantId, branchId, cashierId
    □ status: SessionStatus enum
    □ allocationDraft?, priceSnapshot?, validationResult?, transactionSnapshot?
    □ version: number (concurrency)
    □ createdAt, updatedAt

□ SessionStatus enum:
    DRAFT → ALLOCATING → PRICED → VALIDATED → FROZEN
    (CANCELLED from any state)

□ State transition rules:
    □ Cannot DRAFT → FROZEN (must go through intermediates)
    □ Cannot modify after FROZEN
    □ Can rebuild from PRICED → ALLOCATING (qty change)
```

### Task 3.2 — createSession + allocateInventory

| Attribute | Value |
|-----------|-------|
| Priority | P0 |
| Engineering Estimate | 1.5 hours |
| Dependencies | Task 3.1, Story 2 (adapters) |
| File | `src/services/checkout-session.service.ts` (NEW) |

**Acceptance Criteria**:
```
□ createSession(cart, context) → CheckoutSession
    □ Sets status: DRAFT
    □ Generates sessionId

□ allocateInventory(session, productId, baseQty) → AllocationDraft
    □ Uses BatchProvider adapter (NOT inventory store directly)
    □ Calls AllocationBuilder.buildAllocation()
    □ Updates session: status → ALLOCATING, stores allocationDraft
    □ Session version incremented

□ CheckoutSessionService does NOT:
    □ Run FEFO directly (that's AllocationBuilder)
    □ Access inventory store directly (that's BatchProvider)
    □ Calculate prices (that's PricingEngine)
```

### Task 3.3 — calculatePricing + validate

| Attribute | Value |
|-----------|-------|
| Priority | P0 |
| Engineering Estimate | 1.5 hours |
| Dependencies | Task 3.2 |
| File | `src/services/checkout-session.service.ts` (extend) |

**Acceptance Criteria**:
```
□ calculatePricing(session) → PriceSnapshot
    □ Uses BatchPriceProvider adapter
    □ Calls PricingEngine.calculatePricing()
    □ Updates session: status → PRICED, stores priceSnapshot
    □ Version incremented

□ validate(session) → ValidationResult
    □ Uses InventorySnapshotProvider adapter
    □ Calls AllocationValidator.validateAllocation()
    □ Updates session: status → VALIDATED, stores validationResult
    □ If INVALID → session.status stays at PRICED

□ Each method is independently callable
□ Order enforcement: cannot price without allocation, cannot validate without pricing
```

### Task 3.4 — freeze Orchestration

| Attribute | Value |
|-----------|-------|
| Priority | P0 |
| Engineering Estimate | 1.5 hours |
| Dependencies | Task 3.3, Story 1 (TransactionFreezer) |
| File | `src/services/checkout-session.service.ts` (extend) |

**Acceptance Criteria**:
```
□ freeze(session) → TransactionSnapshot
    □ Full pipeline if needed: allocate → price → validate → freeze
    □ Validates session.status === VALIDATED (or runs validate first)
    □ Calls TransactionFreezer.freeze()
    □ Updates session: status → FROZEN, stores transactionSnapshot
    □ Version incremented

□ After freeze:
    □ TransactionSnapshot is immutable
    □ Session cannot be modified further
    □ Inventory deduction is triggered (handler)
    □ Transaction creation is triggered (handler)
```
