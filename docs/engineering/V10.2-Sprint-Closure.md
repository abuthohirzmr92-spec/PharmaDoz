# LESSONS LEARNED

## What Went Well

1. **Evolutionary Refactor Works.** Memecah menjadi 4 task kecil dengan dual-write di setiap langkah membuat setiap task deliverable dan testable. Tidak ada momen "everything broken".

2. **Architecture Compliance by Construction.** AllocationDraft secara type-level TIDAK BISA menyimpan sellingPrice. Tidak bisa di-compile = tidak bisa dilanggar. Ini lebih kuat daripada dokumentasi.

3. **Pure Functions are Easier to Test.** AllocationBuilder tidak memerlukan mock. Test hanya: input → output. 20 test cases ditulis dan lulus dalam satu iterasi.

4. **Grep as Architecture Gate.** Verifikasi compliance dengan `grep` langsung memberikan confidence. Tidak ada "mungkin ada yang kelewat".

5. **Blueprint as Guardrail.** Setiap kali ragu, kembali ke Blueprint. Setiap kali ada ide "sambil perbaiki X juga", Blueprint menjawab: "itu sprint berikutnya".

## What Could Be Improved

1. **Test coverage pada legacy snapshot building.** Hook masih membangun legacy snapshot secara manual. Ini adalah temporary code yang akan dihapus di V10.3, tapi tetap memerlukan test untuk memastikan tidak rusak selama transisi.

2. **BatchProvider interface belum memiliki implementasi.** Interface sudah didefinisikan di Domain Layer, tapi belum ada adapter yang mengimplementasikannya. Saat ini hook menerima `ProductBatch[]` langsung — ini acceptable untuk V10.2 tapi harus di-address sebelum V10.4.

3. **CV-3 partial resolution.** AllocationDraft memang sudah bersih dari harga, tapi legacy `allocationSnapshot` masih membawa `sellingPrice`. Ini adalah kompromi yang disengaja untuk backward compatibility dan akan diselesaikan di V10.3.
