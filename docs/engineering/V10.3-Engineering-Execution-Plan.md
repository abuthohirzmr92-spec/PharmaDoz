# EXECUTIVE SUMMARY

## What We're Building

Sprint V10.3 mengekstrak **Pricing** dari Allocation dan menambahkan **Validation** capability. Ini adalah langkah kedua dari 4-sprint evolutionary refactor.

## Why This Matters

V10.2 berhasil memisahkan allocation. Tapi `allocationSnapshot` (legacy) masih membawa `sellingPrice` — ini adalah CV-3. V10.3 menyelesaikan ini dengan PricingEngine yang dedicated.

## Sprint Deliverables at a Glance

```
PricingEngine                  — Pure Domain Service (price calculation)
PriceSnapshot                  — Value Object (price breakdown)
AllocationValidator            — Pure Domain Service (stock/expiry change detection)
CV-3 Resolution                — sellingPrice migrated from allocation to pricing
Legacy Compatibility Migration — Consumer migration → validation → legacy removal
```

### Legacy Compatibility Migration — Process

```
Migration is a 3-step process — removal is the LAST step:

Step 1: CONSUMER MIGRATION
  ├── Migrate all consumers from allocationSnapshot → PriceSnapshot + AllocationDraft
  ├── Dual-write: populate both old and new fields during transition
  └── Verify output identical (comparison tests)

Step 2: COMPATIBILITY VALIDATION
  ├── Verify all consumers migrated (grep for allocationSnapshot references)
  ├── Verify grandTotal identical old vs new (30+ scenarios)
  └── Verify no regression in cart display, checkout, receipt

Step 3: LEGACY REMOVAL
  ├── Remove allocationSnapshot field from CartItem
  ├── Remove AllocationSnapshot interface
  └── Remove legacy snapshot building logic from hook

Removal hanya dilakukan SETELAH Step 1 dan Step 2 COMPLETE.
Removal BUKAN aktivitas pertama.
```

## Story 2: AllocationValidator

### AllocationValidator — Responsibility Definition

> **Architecture Board Clarification** — Added during Board Review

AllocationValidator memiliki tanggung jawab yang **terbatas dan spesifik**.

#### ✅ AllocationValidator BERTANGGUNG JAWAB terhadap:

| Concern | Detection |
|---------|-----------|
| **Stock Availability** | Apakah quantity batch saat ini masih mencukupi allocatedQty? |
| **Batch Changes** | Apakah batch yang dialokasikan masih tersedia? (tidak dihapus/dipindah) |
| **Expiry Changes** | Apakah batch sudah expired sejak alokasi? |
| **Allocation Consistency** | Apakah AllocationDraft masih sesuai dengan kondisi inventory terkini? |
| **Inventory Integrity** | Apakah ada perubahan inventory yang mempengaruhi alokasi? |

#### ❌ AllocationValidator TIDAK BOLEH melakukan:

| Concern | Mengapa BUKAN tanggung jawab Validator | Yang Bertanggung Jawab |
|---------|----------------------------------------|------------------------|
| **Price Calculation** | Harga adalah domain Pricing | `PricingEngine` |
| **Discount Validation** | Diskon adalah aturan bisnis Pricing | `PricingEngine` |
| **Promotion Evaluation** | Promo adalah aturan bisnis Pricing | `PricingEngine` |
| **Tax Calculation** | Pajak adalah aturan bisnis Pricing | `PricingEngine` |
| **Member Pricing** | Member price adalah aturan bisnis Pricing | `PricingEngine` |
| **Grand Total Calculation** | Grand total adalah hasil kalkulasi harga | `PricingEngine` |
| **FEFO Re-allocation** | Rebuild adalah operasi Allocation | `AllocationBuilder` |
| **Price Snapshot Rebuild** | Rebuild pricing adalah operasi Pricing | `PricingEngine` |

#### Examples

```
✅ VALID (Validator concern):
   "Batch bat-001 has quantity 45 now, was allocated 50."
   → INVALID: STOCK_CHANGED

   "Batch bat-003 expired on 2026-01-15, it is now 2026-07-05."
   → INVALID: BATCH_EXPIRED

   "Batch bat-002 is no longer in inventory."
   → INVALID: BATCH_CHANGED

   "All allocations match current inventory."
   → VALID

❌ NOT VALIDATOR CONCERN (PricingEngine concern):
   "Selling price of bat-001 changed from 15000 to 16000."
   → This is PRICE_CHANGED → PricingEngine concern.
   Validator does NOT validate selling price correctness.
   (Note: PRICE_CHANGED refers to inventory cost/price changing,
    not selling price validation. That's PricingEngine territory.)

   "Discount should be 10% for member."
   → PricingEngine concern — NOT Validator.

   "Grand total is wrong."
   → PricingEngine concern — NOT Validator.

   "Tax should be 11%."
   → PricingEngine concern — NOT Validator.
```

#### Architecture Boundary

```
┌─────────────────────────────────────────────────────────┐
│                                                          │
│  AllocationValidator                                     │
│                                                          │
│  IN:  AllocationDraft + current Inventory snapshot       │
│  OUT: VALID | INVALID + issues[] (stock/expiry/batch)   │
│                                                          │
│  DOES NOT:                                               │
│  ✗ Calculate prices                                     │
│  ✗ Validate discounts                                   │
│  ✗ Check tax                                            │
│  ✗ Evaluate promotions                                  │
│  ✗ Rebuild allocation                                   │
│  ✗ Access PricingEngine                                 │
│                                                          │
│  PRICING IS PRICINGENGINE'S JOB — NOT VALIDATOR'S        │
│                                                          │
└─────────────────────────────────────────────────────────┘
```
