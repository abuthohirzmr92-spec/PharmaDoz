> **Status**: NON-BLOCKING — Informational only
> **These observations do NOT affect the sprint closure decision.**

## Observation 1 — Price Lookup Optimization

```
Current: priceSnapshot.entries.find(p => p.batchId === entry.batchId)
         O(n) linear search per entry.

For transactions with a very large number of batches (e.g., 100+ entries),
consider pre-building a Map<batchId, PriceEntry> for O(1) lookup:

  const priceMap = new Map(
    priceSnapshot.entries.map(p => [p.batchId, p])
  );
  const price = priceMap.get(entry.batchId);

Status: Deferred.
Not required for V10.3. Current products have 2-3 batches max.
Evaluate when batch counts regularly exceed 10 per product.
```

## Observation 2 — CI Pipeline Automation

```
Current: Architecture compliance verified manually via grep commands.
         TypeScript → vitest → grep sweep → build.

Consider automating architecture compliance as part of CI pipeline:
  • ESLint no-restricted-imports rules
  • Custom script: verify-domain-boundaries.sh
  • Pre-commit hook for architecture grep

Status: Deferred.
Not required for V10.3. Manual verification is reliable but slow.
Automation reduces risk of human error in future sprints.
```

## Observation 3 — Property-Based Testing

```
Current: PricingEngine tested with example-based unit tests.
         Determinism tested with 5-call loop.

Consider property-based testing for stronger guarantees:
  • "For any set of AllocationEntries, grandTotal = sum of subtotals - discount + tax"
  • "For any identical input, output is identical"
  • "For any allocation, pricing never modifies allocation data"

Frameworks: fast-check (JS) or vitest + custom generators.

Status: Deferred.
Not required for V10.3. Example-based tests are sufficient for current scope.
Consider adding when pricing rules (promo, discount) are introduced.
```
