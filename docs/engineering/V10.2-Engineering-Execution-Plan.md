# EXECUTIVE SUMMARY

## What We're Building

Sprint V10.2 mengekstrak **Allocation Domain** dari Cart dan Hook ke dalam Domain Service murni (`AllocationBuilder`). Ini adalah langkah pertama dari 4-sprint evolutionary refactor yang menghilangkan coupling antara Cashier context dan Inventory context.

## Why This Matters

Saat ini (V9), tiga Critical Violations terjadi di setiap transaksi:

| # | Violation | Lokasi | Severity |
|---|-----------|--------|----------|
| CV-1 | Hook mengakses Inventory Store via `getState()` | `use-demo-cashier.ts:209` | CRITICAL |
| CV-2 | Hook memanggil `allocateFefo()` langsung | `use-demo-cashier.ts:215` | CRITICAL |
| CV-3 | AllocationSnapshot mengandung `sellingPrice` | `cashier-store.ts:27` | CRITICAL |

**Sprint V10.2 menargetkan penyelesaian CV-1 dan CV-2. CV-3 ditargetkan selesai di V10.3.**

## Expected Outcome

Setelah Sprint V10.2:
- `AllocationBuilder` tersedia sebagai Domain Service pure
- Hook TIDAK LAGI mengakses Inventory Store
- Hook TIDAK LAGI memanggil `allocateFefo()`
- Allocation tidak mengandung harga
- Checkout flow berfungsi persis sama seperti sebelumnya (dual-write)

### Task 1.3 — Implement AllocationBuilder.build()

| Attribute | Value |
|-----------|-------|
| **Priority** | P0 — Core deliverable |
| **Engineering Estimate** | 2 jam |
| **Dependencies** | Task 1.1, 1.2 |
| **File** | `src/lib/cashier/allocation-builder.ts` (NEW) |

**Purpose**: Implementasi AllocationBuilder sebagai pure Domain Service. Menerima `AllocationInput`, menghasilkan `AllocationDraft`.

**Acceptance Criteria**:
```
□ buildAllocation(input: AllocationInput): AllocationDraft
    □ Pure function — no side effects
    □ Deterministic — input sama → output selalu sama
    □ Semua data dari parameter (tidak membaca global state)

□ buildAllocation() TIDAK mengimpor:
    □ React, React hooks
    □ Zustand (create, useStore, getState)
    □ Supabase client (@/lib/supabase/client)
    □ inventoryRepo (@/lib/repository-instances)
    □ useInventoryStore (@/store/inventory-store)
    □ useCashierStore (@/store/cashier-store)

□ buildAllocation() HANYA mengimpor:
    □ Type definitions (AllocationDraft, AllocationInput, BatchProvider)
    □ FEFO engine (allocateFefo dari @/lib/inventory-demo)
    □ ProductBatch type (dari @/types/inventory)

□ FEFO delegation:
    □ buildAllocation() memanggil allocateFefo() secara internal
    □ allocateFefo() TIDAK diubah sama sekali
    □ FEFO tetap pure — tidak ditambah parameter baru

□ Output Validation:
    □ totalAllocated === sum of all entries.allocatedQty
    □ Jika insufficient stock → throw error dengan pesan jelas
    □ Jika productId tidak ditemukan → kembalikan AllocationDraft kosong
```

**Pseudo-code**:
```typescript
function buildAllocation(input: AllocationInput): AllocationDraft {
  const { productId, baseQty, availableBatches } = input;
  
  // 1. Delegasi ke FEFO engine (existing pure function)
  const fefoResult = allocateFefo(availableBatches, productId, baseQty);
  
  // 2. Validasi kecukupan stok
  const totalAllocated = fefoResult.reduce((sum, a) => sum + a.take, 0);
  if (totalAllocated < baseQty) {
    throw new Error(`Stok tidak mencukupi...`);
  }
  
  // 3. Transform ke AllocationDraft (TANPA harga)
  const entries = fefoResult.map((a, i) => ({
    batchId: a.batchId,
    allocatedQty: a.take,
    allocationOrder: i + 1,
  }));
  
  return {
    draftId: generateId(),
    productId,
    entries,
    totalAllocated,
    generatedAt: new Date().toISOString(),
  };
}
```

**Architecture Rules**:
- ADR-001: CheckoutSession Aggregate Root — AllocationBuilder adalah domain service, bukan aggregate
- ADR-002: Allocation dipisahkan dari Pricing
- ADR-003: FEFO tetap pure
- Invariant 1: Cart tidak tahu Inventory
- Invariant 2: Allocation tidak tahu Pricing
- Invariant 9: FEFO hanya Base Unit
- Invariant 10: Domain Service stateless
- Invariant 13: Domain Service deterministic
- Principle 3: Pure Domain Services
- Principle 4: Stateless Domain Logic

**Definition of Done**:
```
✓ buildAllocation() adalah pure function
✓ FEFO engine dipanggil via delegasi (tidak diubah)
✓ Output: AllocationDraft tanpa sellingPrice
✓ Zero dependency pada React, Zustand, Supabase
✓ Code review oleh Architecture Board member
```
